One repository or several?

A few of you are already building tools you want to share. GitHub keeps every version and lets several people work on the same files. The first question is whether everything goes in one place or each tool gets its own.

Four words you'll need

That's all the vocabulary. Claude does the rest when you ask in plain words.

  • Repository

    A project folder that remembers every version of every file, and who changed what.

  • Organisation

    Background Italia's own space on GitHub. It holds your repositories and decides who sees each one.

  • Save and share

    Keeps a version with a one-line reason and sends it to GitHub, so the others get it.

  • Get latest

    Brings everyone else's changes onto your computer. Do it each time you start.

One repository or several

Both work. They suit different stages.

One team repository

bi-ai/
  CLAUDE.md
  library/     instructions, scorecards
  tools/
    media-screening/
    registry-chart/
    translation/
  • One thing to set up, one place to look
  • Tools reuse the library and each other
  • "Get latest" once and you have it all
  • Everyone in it sees everything
  • Gets crowded as it grows

One repository per tool

bi-library/
media-screening/
registry-chart/
translation/
each with its own CLAUDE.md,
its own people and history
  • You choose who sees each tool
  • A tool can run online or go to a client on its own
  • A clear history per tool
  • More to set up and remember
  • The library has to be linked into each one

What we'll set up: start with one

A team of your size, with tools that are a few weeks old, is better off in one repository. Each tool gets a folder. A tool moves into its own repository when it needs to, and keeps its history when it does.

When a tool gets its own repository

If none of these is true, the tool stays a folder. If one is, ask Claude to move it out.

  1. Different people. Only some of you should see it, or a freelancer needs it and nothing else.
  2. It runs on its own. It becomes a website, a service or something on the office machine.
  3. It leaves the firm. You hand it to a client or a partner.
  4. It's slowing everyone down. Big files, or lots of changes nobody else needs.
To move a tool out Move tools/media-screening into its own repository in our organisation, with its history. Give it a CLAUDE.md that points to our library, then remove the folder here and say where it went in the README.

Your account

Ten minutes each. Use your work email.

  1. Sign up at github.com with your Background Italia email. The free plan is all you need.
  2. Add a passkey under Settings, Password and authentication. It's your fingerprint or face, so no extra code to type.
  3. Send Alice your username. She adds you to the organisation and you accept the email.
  4. Sign in to VS Code with GitHub: the person icon at the bottom left.

Bring your project in

Keep working where you are until the repository exists. Then each of you brings one project in, with Claude checking it first.

Put the repository in a plain folder such as Documents/GitHub. Not in Google Drive, OneDrive, Dropbox or iCloud: the sync and GitHub both write to the same hidden files and damage each other.

Once, to get the team repository Clone our team repository bi-ai into Documents/GitHub and open it.
Then, for your project Copy my project from <paste the path> into tools/<tool name>/. Before you save anything, check it for client names, personal details, passwords, API keys and files over 50 MB, and show me what you found. Write a short README.md: what the tool does, how to start it and who looks after it. Then save and share with the message "Add <tool name>".

If Claude finds something, it goes on the shared drive or on the list of files GitHub ignores, and the tool reads it from there.

Every day after that Get latest.

And when you're done: "Save and share: <what you changed>".

If two of you changed the same lines, Claude says so and suggests how to combine them. Read it, then say which version to keep.
