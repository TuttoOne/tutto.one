You still sign it off

Think of Claude as someone you've hired to do the work. You'd read what a new contractor sends back before your name goes on it, and the same goes here.

Check it the way you'd check a new contractor's first piece of work.The first time is slow. Every error you note becomes a rule, so the next batch needs less checking.

  • Start small. Check one module line by line before you ask for ten.
  • Check against something Claude didn't write: your subject experts and your own learner material.
  • Write each error down (format, wording, facts), then give Claude the list.
  • Too much to read? Ask for a summary, and add "keep answers short" to your CLAUDE.md.
  • Keep learner names, ID numbers and marks out of the folder.

Clarifying voice.md

CLAUDE.md is the one Claude reads by itself

I mentioned a voice.md alongside CLAUDE.md. The difference matters: CLAUDE.md is the only file Claude reads at the start of every chat. A voice.md, a style guide or a format file is read when CLAUDE.md points to it.

That's what Laetitia's Claude did this morning: it kept CLAUDE.md short and pointed to the HSA format instead of copying every rule in. That's the right way round.

There are two ways to point. Write @house-style.md and the file is loaded every time. Write "follow house-style.md when you write learner material" and Claude opens it when the job needs it. Skills like the HSA format work the second way: Claude uses one when the job matches, or straight away when you type /hsa-format.

Paste into Claude in your HSA folderMake a CLAUDE.md for this folder from what we've agreed so far. Keep it under 40 lines. Include: - Write in English (South Africa) for NQF 4 learners. - Keep answers short. Give me a summary first and the detail only if I ask. - Use the HSA format skill for any learner material. - Only use the documents in this folder unless I say otherwise. If you need an outside source, use official ones (Government Gazette, board notices, SAPC, WHO) and tell me each time you use one. - Never put learner names, ID numbers or marks in a file. Point to other files instead of copying them in. Show me the file before you save it.
Clarifying the website block

A request in CLAUDE.md, a rule in settings

When I talked about blocking websites, the block sits in a settings file. Claude reads CLAUDE.md and tries to follow it. Settings are rules the program enforces, so Claude can't talk its way round them.

In CLAUDE.md

"Use official sources and tell me when you do."

  • Flexible. Claude can still settle a contradiction, like it did for Elsa.
  • It's a request. In a long chat Claude can drift, as Laetitia found.

In .claude\settings.json

Claude has to ask you before every search, or can't search at all.

  • Enforced every time, in that folder only.
  • "Ask" is the middle ground Elsa wanted: you see each source and say yes or no.
  • Change it back when you do want open research in that folder.
What the file says (ask first){ "permissions": { "ask": ["WebSearch", "WebFetch"] } }

You don't need to type it. Ask Claude: "In this folder's .claude settings, make Claude ask me before any web search or web page."

For a hard stop, change ask to deny. Use both together: the CLAUDE.md rule says which sources are good, and the setting makes sure you see each one.

Sharing your rules with each other

Not everyone can reach the same OneDrive, so you chose a Teams channel. That's a good place to start.

A Teams channel, now

Everyone can reach it today.

  • Put the HSA folder (with its .claude folder) in the channel's Files. Each of you copies it to your laptop and opens it in VS Code.
  • Copies drift. Agree one owner per file and post in the channel when you change it.

A private GitHub repository, later

When several of you edit the same rules.

  • Every change saved with who, when and why. Go back to any version, and merge two people's work.
  • Claude does the saving and describes the changes, so you don't learn commands.
  • A new account, which IT may want to approve first.

Fresh chats and a tidy-up

Start a new chat for each new piece of work. It's like starting the day after a good night's sleep. The chat forgets the last conversation and goes back to your CLAUDE.md. Elsa noticed it still remembers some things: those come from the files in the folder and Claude's own notes, which is the point.

Put a reminder in your calendar for two or three months from now. Read your CLAUDE.md files and Claude's notes, delete what's out of date and fix rules that contradict each other. You can ask Claude to do the first pass: "read every CLAUDE.md in these folders and list anything that clashes or is out of date."
