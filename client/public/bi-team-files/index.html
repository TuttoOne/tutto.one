One team library

Put a folder called team-library on the shared drive you already use (Google Drive or SharePoint) and sync it to everyone's computer. It holds how you do the work. Client documents stay in the case folder.

The job folders are the system-template/ from your starter kit, one copy per job. Each job has one owner who looks after its files. Anyone can use them.

Point to it, don't copy it

When you copy the files into each case, you end up with ten versions and nobody knows which is right.

Copy into every case

v1v2v2bfinal?

A fix made in one case never reaches the others.

Point to the library

one

Fix it once and every case gets the fix.

There are two ways to point. Use the first, and the second if you'd rather not open a workspace each time.

Add it to your workspace

Open the case folder in VS Code, drag team-library into the side panel and choose Add Folder to Workspace. Save the workspace when you close. The workspaces guide has a screenshot for every step.

One line in CLAUDE.md

In the case folder's CLAUDE.md, write @ and the full path to the library file. Claude reads it every time, as if it were in the folder. Get the path with right-click, Copy Path, because it's different on each computer.

A case CLAUDE.md that points to the library This case is a due diligence report review.
Follow @/Users/alice/Google Drive/team-library/jobs/dd-report-review/INSTRUCTIONS.md
Check every draft against @/Users/alice/Google Drive/team-library/jobs/dd-report-review/SCORECARD.md
Write the way @/Users/alice/Google Drive/team-library/VOICE.md describes.

The first time, Claude asks whether it may read files from outside the folder. Say yes.

Don't use a Mac alias or a Windows shortcut. Claude sees it as a small file of its own and can't see inside the folder it points to. That's the most likely reason it didn't work when Alice and Gabriel tried.

Keep it up to date

The files only get better if your corrections go back into them. Alice's subcontractor report is the example: she made the last small changes in the final report, and now they need to go into the instructions so the next report has them too.

  1. The owner makes the changes. Anyone else adds a note to LOG.md or tells the owner.
  2. Watch for conflict copies. Two people editing the same file at once on a shared drive makes a second copy. Give both to Claude and ask it to merge them.
  3. Tidy every couple of months. Ask Claude to make the files shorter and easier to read. Tools change, so your files should too.
After you change the final version by hand My final version is <paste the path>. Compare it with your draft and list what I changed. Then update INSTRUCTIONS.md in the team library so the next draft has these changes without me making them. Add a line to LOG.md with today's date, what changed and why.
