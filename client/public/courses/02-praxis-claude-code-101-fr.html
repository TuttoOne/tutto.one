Tutto.Leçon 1 · Fondamentaux
Leçon 1

Le chat répond. Un agent agit.

Claude.ai vous rend du texte et attend. Claude Code va dans vos fichiers, votre terminal et votre code, et fait le travail lui-même.

Un agent lit et comprend le code, modifie des fichiers dans tout le projet, exécute des commandes dans le terminal et cherche sur le web — puis décide de la suite.

03
Tutto.Leçon 2 · Fondamentaux
Leçon 2

La boucle agentique

Tout le reste repose là-dessus : le prompt, la collecte du contexte, l'action, la vérification — et on reboucle jusqu'à ce que le résultat tienne.

Quatre éléments font tourner la boucle : la boucle elle-même, une fenêtre de contexte gérée, les outils qu'il peut appeler, et les permissions que vous contrôlez. C'est cette combinaison qu'une fenêtre de chat n'a pas.

04
Tutto.Leçon 3 · Installation
Leçon 3

Cinq endroits où il tourne

Le même agent tourne à cinq endroits. Où que vous le lanciez, il voit ce dossier et tout ce qu'il contient.

Vous voulez les dernières nouveautés ? Le terminal. Vous le voulez dans votre éditeur ? VS Code ou JetBrains. Vous le voulez au travail pendant que vous faites autre chose ? Desktop. Vous travaillez à distance depuis un dépôt GitHub ? Le web.

Tutto.Leçon 4 · Installation
Leçon 4

Une seule touche règle votre niveau de contrôle

Appuyez sur Shift + Tab pour changer votre degré d'implication. Il n'y a pas de bonne réponse, seulement ce qui vous met à l'aise.

Le mode plan est le point de départ sûr pour tout ce qui est complexe : il lit votre code, pose ses questions, et vous rend un plan avant qu'un seul fichier ne bouge.

Tutto.Leçon 5 · La méthode
Leçon 5 — si vous ne retenez qu'une chose

Explorer → Planifier → Coder → Valider

La plupart des gens passent directement au « écris le code » et corrigent le tir indéfiniment. Voici le déroulé qui évite de tout refaire.

Rendez « correct » explicite (critères de réussite), donnez-lui des outils et une suite de tests pour vérifier, et s'il bute toujours sur le même mur : dites-lui d'enregistrer la correction dans CLAUDE.md.

07
Tutto.Leçon 6 · La méthode
Leçon 6

Le contexte est une mémoire de travail : il se remplit

Chaque fichier lu, commande lancée et message envoyé prend de la place. Trois commandes le gardent utilisable.

Consommer moins de contexte : soyez précis (les prompts vagues coûtent plus cher, pas moins), coupez les serveurs MCP que vous n'utilisez pas, et confiez l'exploration à un subagent qui ne renvoie que la réponse.

08
Tutto.Leçon 7 · La méthode
Leçon 7

Un regard neuf avant de pousser

L'agent qui a écrit le code porte ses propres biais. Un subagent le relit à froid, dans son propre contexte.

Gardez le relecteur en lecture seule : il signale les problèmes, il ne modifie pas. Versionnez-le dans le repo pour que toute l'équipe relise de la même façon.

09
Tutto.Leçon 8 · Personnaliser
Leçon 8

CLAUDE.md — la mémoire qui survit à la session

Un simple fichier qui contient les règles de votre travail, lu au début de chaque session, pour que Claude démarre déjà briefé.

C'est un script d'accueil pour votre code, ajouté à chaque prompt. Committez-le pour que l'équipe partage une seule source de vérité — gardez-le compact et limité à l'essentiel.

Notion cléTrois niveaux, empilés : projet ./CLAUDE.md (committé, équipe), local ./CLAUDE.local.md (ignoré par git, rien que pour vous), utilisateur ~/.claude/CLAUDE.md (tous les projets de votre machine). → tout le détail dans les notes du formateur.

Tutto.Leçon 9 · Personnaliser
Leçon 9

Les subagents : déléguer le gros du travail

Un subagent fait l'exploration désordonnée dans son propre contexte et ne vous rend que la réponse. Votre contexte principal reste propre.

« Où sont les endpoints d'authentification ? » — le subagent lit la moitié du code pour le savoir, mais seule la réponse revient. Le trajet n'encombre jamais votre fenêtre principale.

Tutto.Leçon 10 · Personnaliser
Leçon 10

Les skills : une capacité chargée seulement quand elle sert

Un skill s'annonce avec un nom et une ligne. Claude charge les instructions complètes seulement quand il décide de l'utiliser.

C'est là le gain par rapport au chargement de tout d'emblée : les skills gardent la fenêtre de contexte légère. (Le cours renvoie à un module dédié, « Introduction to agent skills », pour aller plus loin.)

12
Tutto.Leçon 11 · Personnaliser
Leçon 11

MCP — un pont vers tout ce qui est hors du code

L'essentiel de votre contexte vit dans des bases de données, des applications et des dépôts. MCP permet à Claude Code d'y accéder via des outils.

Attention au coût : chaque serveur charge ses définitions d'outils dans le contexte, utilisées ou non. Lancez /mcp et désactivez ce dont vous ne vous servez pas — un CLI comme gh, ou un skill, est souvent plus léger.

13
Tutto.Leçon 12 · Personnaliser
Leçon 12

Les hooks — ce qui doit se passer, toujours

Un hook est une règle qui s'exécute automatiquement à des moments fixes du cycle de vie — à chaque fois, sans exception.

Formatage automatique à chaque modification, journalisation de chaque commande pour la conformité, écritures bloquées en production. Si ça doit arriver à chaque fois sans faute, ne le mettez pas dans un prompt : mettez-le dans un hook.
