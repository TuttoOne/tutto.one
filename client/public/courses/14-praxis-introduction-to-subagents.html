Tutto.Lesson 1 · Concept
Lesson 1

A subagent works in its own context

It gets a role and a task, does the messy work out of sight, and hands back only the answer.

Built in already: a general-purpose agent, Explore for fast search, and Plan for plan-mode research. The tradeoff — you lose sight of how it got there.

03
Tutto.Lesson 2 · Build
Lesson 2

Make one with /agents — Claude writes the file

Describe what you want; Claude generates the name, description and system prompt. It's a markdown file with a short YAML header.

Scope it project-level (this repo) or user-level (everywhere). Put the word "proactively" in the description and Claude will delegate without being asked.

04
Tutto.Lesson 3 · Design
Lesson 3

Four things separate a worker from a wanderer

A good subagent is steered by its description, knows when to stop, reports what it hit, and touches only what it must.

The description does double duty: it decides when the subagent launches and shapes the task prompt the main agent writes for it. Vague in, vague out.

05
Tutto.Lesson 4 · Judgment
Lesson 4 — if you take one thing away

Does the intermediate work matter?

That one question decides it. If you don't need to watch the journey, delegate. If you do, keep it in your main thread.

Why code review makes the list: Claude critiques code more honestly when it didn't write it. A fresh-context reviewer beats asking the thread that built the feature.

The whole thing, in one line

Isolate the work.
Shape the output.
Delegate by judgment.

A subagent runs in its own context and returns a summary. Build it with /agents, steer it with a sharp description and an output format, and reach for it only when the journey doesn't matter.
