Tutto.Leçon 1 · Les fondations
Leçon 1

De l'autocomplétion à un coéquipier qui agit

Un assistant de code se situe sur un spectre. À une extrémité, il devine votre ligne suivante ; à l'autre, il lit votre projet et fait le travail.

Un agent ne se contente pas de parler du code — il travaille dans votre terminal et votre repo : il lit les fichiers, les modifie, exécute des commandes et décide de la suite.

03
Tutto.Leçon 2 · Les fondations
Leçon 2

À quoi ressemble vraiment une session

Vous demandez en langage courant. Claude lit les fichiers concernés, fait les modifications, les exécute et vous montre le résultat à vérifier.

Le cours fait la démonstration sur une petite application de génération d'interfaces (uigen) — mais elle n'a rien de particulier : vous pouvez suivre sur une base de code à vous.

Tutto.Leçon 3 · Les bases
Leçon 3

Une seule commande à installer

Une ligne dans votre terminal, quelle que soit la plateforme. Ensuite, lancez claude, choisissez un thème et connectez-vous.

Une erreur « command not found », réseau ou permissions ? La page « Troubleshoot installation » de la documentation est le premier réflexe. Passer par Bedrock, Vertex ou Foundry demande sa propre configuration.

Tutto.Leçon 4 · On démarre
Leçon 4

Pointez-le sur un vrai projet

Claude Code est plus intéressant quand il a de quoi travailler. Le cours fournit une petite application de génération d'interfaces à explorer.

La clé API Anthropic est facultative ; elle ne sert qu'à la génération d'interfaces de l'application. Node JS est le seul vrai prérequis.

Tutto.Leçon 5 · On démarre
Leçon 5

Le contexte : comment Claude apprend votre projet

Claude ne connaît que ce qui se trouve dans sa fenêtre de contexte. Vous y mettez les bons fichiers, les bonnes sorties et les bonnes règles avant de demander.

Soyez précis sur ce qui compte. Moins Claude a à deviner, moins il s'égare — et moins chaque exécution consomme de contexte (et d'argent).

Tutto.Leçon 6 · Se lancer
Leçon 6

Modifier le code : décrivez, relisez le diff

Vous dites ce que vous voulez ; Claude modifie les fichiers et vous montre un diff. Vous validez, vous ajustez, et seulement ensuite vous committez.

Vous gardez la main : chaque modification est relisible, et vous pouvez orienter, annuler ou rediriger avant que quoi que ce soit n'arrive dans le dépôt.

Tutto.Leçon 7 · Piloter et personnaliser
Leçon 7

Maîtriser le contexte : gardez la fenêtre légère

Une longue session remplit la fenêtre. Trois commandes la gardent centrée sur ce qui compte maintenant.

Effacez entre deux tâches sans rapport ; compactez pour garder un fil long en vie ; vérifiez /context quand les réponses commencent à dériver — en général, la fenêtre est pleine.

09
Tutto.Leçon 8 · Piloter et personnaliser
Leçon 8

Commandes personnalisées : enregistrez un prompt que vous réutilisez

Un prompt que vous tapez souvent devient une commande slash — un fichier Markdown que Claude exécute à la demande.

Tout ce que vous vous surprenez à réexpliquer — une checklist de relecture, une routine de mise en production — est un candidat. Écrivez-le une fois ; appelez-le avec un slash.

Concept cléParamètres d'exécution : $ARGUMENTS reprend tout ce que l'utilisateur a tapé ; $1 $2 $3 prennent des arguments positionnels. → détail complet (!`cmd`, @file, argument-hint) dans les notes du formateur.

10
Tutto.Leçon 9 · Piloter et personnaliser
Leçon 9

MCP : atteindre les outils en dehors de votre code

L'essentiel de ce dont vous avez besoin vit dans d'autres systèmes : tickets, documents, bases de données. MCP y connecte Claude Code sous forme d'outils.

Attention au coût : chaque serveur charge ses définitions d'outils dans le contexte, que vous les utilisiez ou non. Ajoutez ce dont vous avez besoin, et désactivez le reste avec /mcp.

Notion cléFaire tourner MCP dans GitHub Actions demande un modèle de permissions à deux niveaux : configurer le serveur (--mcp-config) et autoriser chaque outil par son nom (mcp__server__tool). Les deux sont obligatoires. → tout le détail dans les notes du formateur.

Tutto.Leçon 10 · Piloter et personnaliser
Leçon 10

GitHub : de la modification locale à la pull request

Claude Code pilote la CLI GitHub pour commiter, pousser et ouvrir une PR — et l'app GitHub peut l'exécuter en CI dès que vous la mentionnez.

La ligne du haut, c'est vous, en local. La ligne du bas se passe de vous : mentionnez @claude sur une issue ou une PR et l'app GitHub lance Claude Code dans la CI pour trier, relire ou implémenter.

12
Tutto.Leçon 11 · Hooks & SDK
Leçon 11 — si vous ne retenez qu'une chose

Un prompt est une demande. Un hook est une garantie.

Demander à Claude de « toujours lancer le formateur », c'est une demande qu'il peut oublier. Un hook est une commande shell qui s'exécute à chaque fois, sans exception.

Le but d'un hook : transformer ce que vous demandez à Claude de faire en ce qui arrive toujours . Exécuté par le harness, pas par le modèle — si quelque chose doit arriver à chaque fois, ne le mettez pas dans un prompt. C'est ce qui fait passer une équipe de « on le relira après » à « ça ne peut pas arriver du tout ».

Concept cléLes prompts sont probabilistes ; les hooks sont déterministes — c'est tout l'intérêt. → les trois formes (garantir / bloquer / injecter du contexte) sont dans les notes du formateur.

Tutto.Leçon 12 · Hooks & SDK
Leçon 12

Définir un hook : événement → matcher → commande

Un hook, c'est trois choses dans settings.json: quel événement du cycle de vie, quel outil il matche, et la commande à exécuter.

PreToolUse est le seul hook qui s'exécute avant un outil, donc c'est le seul qui peut arrêter un appel — exit 2 (ou renvoyez "permissionDecision":"deny") et le rm -rf ou le commit sur main est bloqué avant qu'il n'arrive, pas après.

Concept cléLe hook voit le nom de l'outil et son entrée, vous filtrez donc selon des conditions — bloquer Bash sur une liste d'interdits, ou toute édition touchant .env. → notes formateur pour les décisions autoriser / bloquer / demander.

14
Tutto.Leçon 13 · Hooks & SDK
Leçon 13

Les hooks en pratique : les partager, les déboguer

Deux problèmes réels que le cours résout — partager les hooks entre machines, et connaître la forme de l'entrée qu'un hook reçoit.

L'entrée sur stdin change selon l'événement et selon l'outil, donc commencez par la journaliser. Les chemins absolus sont recommandés pour la sécurité — d'où le $PWD dans les settings partagés, que setup remplace.

Tutto.Leçon 14 · Hooks & SDK
Leçon 14

Le SDK : Claude Code comme brique de construction

Le même agent que vous lancez dans le terminal peut être intégré à vos propres scripts et applications via le SDK.

Enveloppez la boucle agentique — outils, contexte, permissions — dans vos propres logiciels, et Claude Code cesse d'être un simple CLI pour devenir un composant sur lequel vous construisez.
