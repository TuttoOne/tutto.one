Tutto.Lesson 1 · Foundation
Lesson 1

M×N integrations become M+N

Without a standard, every app wires up to every tool by hand. MCP is the standard connector that ends the tangle.

MCP is a standard, like USB-C for AI: build to the protocol once and every compliant tool just works. It also splits the work — app builders on one side, tool builders on the other.

03
Tutto.Lesson 2 · Foundation
Lesson 2

Host, client, server — one client per server

The app you use is the host. Inside it, each client holds one connection to one server, and the server wraps the real tool or data.

Messages travel as JSON-RPC over a transport: stdio for a local server, HTTP for a remote one. The host can hold many clients at once, but each client talks to exactly one server.

04
Tutto.Lesson 3 · Foundation
Lesson 3

A server is a few lines to start

The Python SDK's FastMCP does the protocol plumbing. You create a server, register capabilities, and run it over a transport.

stdio runs the server as a local subprocess of the host; HTTP exposes it as a remote service. Same server code either way — the transport is just how messages travel.

05
Tutto.Lesson 4 · Tools
Lesson 4

Tools — actions the model can choose to call

Decorate a function and its name, docstring and typed arguments become a schema the model reads. The model decides when to use it.

A clear name and description matter: that text is all the model has to decide whether and how to call the tool. Treat the docstring as a prompt, not a comment.

06
Tutto.Lesson 5 · Tools
Lesson 5

Test the server before wiring it to an app

The Inspector connects straight to your server — no LLM involved. List what it exposes, call each tool by hand, read the raw response.

Debug the server on its own first. If the Inspector can list and call everything cleanly, the problem later is in the client wiring — not the server.

07
Tutto.Lesson 6 · Tools
Lesson 6

The client feeds tools to the model, in a loop

Your client lists the server's tools, hands their schemas to Claude, runs whatever Claude asks for, and feeds the result back — until it has an answer.

This is the same agentic loop a chat window doesn't have: the model can act, see the result, and decide what to do next. MCP is just how the tools get there.

08
Tutto.Lesson 7 · Resources & prompts
Lesson 7

Resources — data to pull in, addressed by URI

Read-only data the server exposes at an address. No side effects: think GET, not POST.

A URI scheme like docs:// names the data. Direct resources return a collection; templated ones take a parameter to fetch exactly one — a single document, a single record.

09
Tutto.Lesson 8 · Resources & prompts
Lesson 8

The app decides which resources to load

Unlike tools, the model doesn't reach for resources. The application — often the user — chooses what context to bring in.

That's the difference from a tool: a tool is the model's to call, a resource is the app's to load. Same server, two different control models — which is the heart of MCP.

10
Tutto.Lesson 9 · Resources & prompts
Lesson 9

Prompts — reusable templates the author ships

A tested, parameterized prompt the server exposes, so the right wording is baked in instead of reinvented every time.

Prompts move hard-won phrasing out of people's heads and into the server. The author tunes it once; everyone else just calls it and gets the good version.

11
Tutto.Lesson 10 · Resources & prompts
Lesson 10

Prompts surface as slash commands

The client lists the server's prompts and offers them to the user. Pick one, fill the arguments, and it expands into the full message.

If you've used a slash command in Claude Code, you've used an MCP prompt. The server ships the command; the client makes it a one-keystroke action.

Tutto.Lesson 11 · Recap
Lesson 11 — if you take one thing away

Three primitives, three owners

The whole protocol, in one picture: what the server exposes, and who gets to trigger each one.

Everything in the course hangs off this: tools the model calls, resources the app loads, prompts the user triggers. Get the owners straight and the rest follows.
