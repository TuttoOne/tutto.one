Tutto.Chapter 1 · Talk to Claude
Chapter 1

A conversation is a list of messages

You send the whole message list each turn; Claude appends its reply. A system prompt sets the rules; temperature, max tokens and streaming shape the output.

The Bedrock difference is the door, not the shape: AWS credentials and a region instead of an Anthropic key, and a Bedrock model id. Everything past this slide is the same SDK.

03
Tutto.Chapter 2 · Make it reliable
Chapter 2

Measure the prompt, don't eyeball it

"Looks good" doesn't scale. Build a test set, run the prompt across it, and grade the answers — so you know a change is an improvement.

Claude can generate the test dataset for you. Model-based grading handles open-ended answers; code-based grading handles anything with a right answer.

04
Tutto.Chapter 3 · Make it reliable
Chapter 3

Clarity first, examples last

Reach for the techniques in order. Most prompts are fixed by being clearer, not by being cleverer.

Each rung costs more context than the last. Examples (few-shot) are the strongest lever — and the most expensive, so reach for them once the cheaper rungs are spent.

05
Tutto.Chapter 4 · Give it reach
Chapter 4 — if you take one thing away

Claude asks, your code answers

Tool use is the pivot of the whole course. Claude can't run your code — so it asks, in structured JSON, and you run it and hand the result back.

Everything else is this one exchange, repeated: multiple tools, multi-turn, batching, structured-data extraction, and built-ins like the text-editor tool. Master this and agents are just this in a loop.

06
Tutto.Chapter 5 · Give it reach
Chapter 5

Retrieve the right context, then answer

Claude only knows what's in the prompt. RAG finds the few relevant passages from your own documents and puts them there.

Two searches beat one: semantic for meaning, BM25 for exact terms. Reranking sharpens the shortlist; contextual retrieval adds a line of context to each chunk so it survives being torn from its document.

07
Tutto.Chapter 6 · Give it reach
Chapter 6

Beyond text

The same message API carries more than words: it can think longer, read documents, cite its sources, and cache to cut your bill.

Caching has rules worth knowing: it covers a stable prefix, so put the unchanging parts first. On repeated calls over the same documents, that prefix is read from cache instead of reprocessed.

08
Tutto.Chapter 7 · Build systems
Chapter 7

One protocol: tools, resources, prompts

Wire a capability once as an MCP server, and any MCP client — Claude Code, your own app — can use it. No bespoke glue per integration.

Tools do, resources inform, prompts reuse. The protocol is the contract between them, so the same server drops into any client unchanged.

09
Tutto.Chapter 8 · Build systems
Chapter 8

An agent is the loop plus tools plus autonomy

Everything earlier composes here: prompting, tools, retrieval and MCP become an agent that runs its own loop until the job is done.

Good agents share qualities: clear tools, a way to verify their own work, and bounded autonomy. Computer Use is the far end — Claude operating a screen when there's no API to call.
