Tutto.Lesson 1 · Foundation
Lesson 1

From autocomplete to a teammate that acts

A coding assistant sits on a spectrum. At one end it guesses your next line; at the other it reads your project and does the work.

An agent doesn't just talk about the code — it works inside your terminal and your repo: reading files, editing across them, running commands, and deciding what to do next.

03
Tutto.Lesson 2 · Foundation
Lesson 2

What a session actually looks like

You ask in plain English. Claude reads the relevant files, makes the edits, runs them, and shows you the result to review.

The course demos this on a small UI-generation app (uigen) — but nothing is special about it: you can follow along on a codebase of your own.

Tutto.Lesson 3 · Foundation
Lesson 3

One command to install

One line in your terminal, whatever the platform. Then run claude, pick a theme and sign in.

Hit a "command not found", network or permissions error? The docs' "Troubleshoot installation" page is the first stop. Running through Bedrock, Vertex or Foundry has its own setup.

Tutto.Lesson 4 · Get going
Lesson 4

Point it at a real project

Claude Code is more interesting with something to work on. The course ships a small UI-generation app to explore.

The Anthropic API key is optional; it only powers the app's own UI generation. Node JS is the one real prerequisite.

Tutto.Lesson 5 · Get going
Lesson 5

Context in: how Claude learns your project

Claude only knows what's in its context window. You pull the right files, output and rules in before you ask.

Be specific about what matters. The less Claude has to guess, the less it wanders — and the less context (and money) each run burns.

07
Tutto.Lesson 6 · Get going
Lesson 6

Making changes: describe it, review the diff

You say what you want; Claude edits across the files and shows you a diff. You approve, refine, and only then commit.

You stay in control: every edit is reviewable, and you can steer, undo or redirect before anything lands in the repo.

Tutto.Lesson 7 · Drive & customise
Lesson 7

Controlling context: keep the window lean

A long session fills the window. Three commands keep it focused on what matters now.

Clear between unrelated tasks; compact to keep a long thread alive; check /context when answers start to drift — that's usually a full window.

09
Tutto.Lesson 8 · Drive & customise
Lesson 8

Custom commands: save a prompt you reuse

A prompt you type often becomes a slash command — a Markdown file Claude runs on demand.

Anything you find yourself re-explaining — a review checklist, a release routine — is a candidate. Write it once; call it with a slash.

10
Tutto.Lesson 9 · Drive & customise
Lesson 9

MCP: reach the tools outside your code

Most of what you need lives in other systems — issues, docs, databases. MCP connects Claude Code to them as tools.

Watch the cost: every server loads its tool definitions into context whether you use them or not. Add what you need, and disable the rest with /mcp.

11
Tutto.Lesson 10 · Drive & customise
Lesson 10

GitHub: from local change to pull request

Claude Code drives the GitHub CLI to commit, push and open a PR — and the GitHub app can run it in CI when you mention it.

Top row is you, locally. Bottom row is hands-off: tag @claude on an issue or PR and the GitHub app runs Claude Code in CI to triage, review or implement.

12
Tutto.Lesson 11 · Hooks & SDK
Lesson 11 — if you take one thing away

A prompt is a request. A hook is a guarantee.

Asking Claude to "always run the formatter" is a request it might forget. A hook is a shell command that runs every time, no exceptions.

Hooks are run by the harness, not the model — that's what makes them reliable. If something must happen every time, don't put it in a prompt.

13
Tutto.Lesson 12 · Hooks & SDK
Lesson 12

Defining a hook: event → matcher → command

A hook is three things in settings.json: which lifecycle event, which tool it matches, and the command to run.

A PreToolUse hook that exits 2 blocks the action — that's how you stop an rm -rf or a commit to main before it happens, not after.

14
Tutto.Lesson 13 · Hooks & SDK
Lesson 13

Hooks in practice: share them, debug them

Two real problems the course solves — sharing hooks across machines, and knowing the shape of the input a hook receives.

The input on stdin changes per event and per tool, so log it first. Absolute paths are recommended for security — which is why shared settings use a $PWD placeholder that setup expands.

15
Tutto.Lesson 14 · Hooks & SDK
Lesson 14

The SDK: Claude Code as a building block

The same agent you run in the terminal can be embedded in your own scripts and apps through the SDK.

Wrap the agentic loop — tools, context, permissions — inside your own software, and Claude Code stops being just a CLI and becomes a component you build on.
