Tutto.Access · foundations
Models

One family, three sizes

Same family, traded along one axis: faster and cheaper at one end, more capable at the other. You pick per task, not once forever.

The same code calls any of them — you change one model string. Start on Sonnet; drop to Haiku when volume bites, reach for Opus when the task is genuinely hard.

03
Tutto.Access · foundations
Vertex access

Claude through your own Google Cloud

Two gates, then the same SDK. Enable the model in Vertex, sign in with gcloud, and the Anthropic library uses your Google credentials automatically.

The draw of Vertex: billing, regions and governance live inside Google Cloud you already run. From the code's side, only the client constructor changes — everything after is the standard Messages API.

Tutto.Access · foundations
The request

Every call is a Messages request

One shape underneath everything: a model, a list of messages, and a few limits. Claude replies with content blocks — streamed token by token if you ask.

Streaming changes nothing about the request, only how the answer comes back: useful for chat UIs and long replies where waiting for the whole thing feels broken.

Tutto.Access · foundations
Multi-turn

The API has no memory

Each call starts cold. A "conversation" is just you re-sending the whole history every time — the model never remembers the last turn on its own.

This is why long chats get slower and pricier: every turn re-reads the entire transcript. It is also why you are in full control of what the model can and cannot see.

Control

Four knobs shape the output

Before you reach for clever prompting, these are the dials the API hands you directly.

Temperature is widely misread: lower it for extraction, classification and anything you'll parse; raise it for brainstorming and copy. For structured output, the tool schema (slide 9) is often the firmest grip.

Tutto.Evaluation
The eval loop

Don't eyeball it — measure it

A prompt that "seems fine" on three examples breaks on the fourth. An eval makes "better" a number you can move on purpose.

Code-based grading where the answer is checkable; model-based grading where quality is a judgement call. Claude can even generate the test set — then you've got a dial, not a hunch.

Tutto.Prompting
Four techniques

Most prompting is four moves

When the eval says the prompt is the problem, these four fixes carry the load — roughly in this order of return.

The instinct most people fight is over-trusting hints. The model isn't a mind-reader: vagueness costs more, not less. Examples are the strongest fix — and the one people skip.

Tutto.Tool use
The tool-use loop — if you take one thing away

Claude can't run code — it asks you to

This loop is the engine under tools, agents, MCP and computer use. The model never executes anything itself; it requests, you run, you return.

A tool is just a function plus a description of when to use it. Once you can run this loop, "an agent" is only this loop left running until the job is done.

10
Tutto.Tool use
Built-in tools

Some tools you don't have to build

You write your own functions — but Anthropic ships ready-made tools, and a batch path for when you're running thousands of calls, not one.

Reach for structured-data-via-tools whenever you need a guaranteed shape: it's far more reliable than asking nicely for JSON in prose.

11
Tutto.Retrieval
The RAG flow

Give the model your data at question time

Claude doesn't know your documents. RAG fetches the few relevant pieces and pastes them into the prompt, so the answer is grounded in your sources.

The model's job never changes — it just answers a prompt. RAG is all about putting the right paragraphs into that prompt before it ever sees the question.

12
Tutto.Retrieval
Making it good

Naive retrieval misses — here's the ladder

Most RAG fails at the "retrieve" step: it pulls the wrong chunks. Each rung lifts what comes back before Claude ever sees it.

Start simple — embeddings alone often suffice. Add lexical search when exact terms matter, reranking when you retrieve a lot, contextual retrieval when chunks are losing their thread.

Tutto.Features
Native capabilities

Built in, no extra plumbing

Four things the model does out of the box — each is a parameter or a content block, not a separate system you have to stand up.

Extended thinking is the one to reach for deliberately: turn it on for genuinely hard reasoning, leave it off for routine calls where it just adds latency and cost.

14
Tutto.Features
Prompt caching

Pay once for the part that repeats

If the front of every request is the same — a long system prompt, a tool list, a big document — cache it. Later calls read it back cheaply instead of re-billing it.

The discipline it forces is good architecture anyway: stable context up front, the user's variable input at the end. That ordering is what makes the cache hit.

15
Tutto.Connect & act
MCP

One standard plug for context

Tool use is powerful but bespoke — you wire each integration by hand. MCP standardises the socket: build a server once, any client connects to it.

Think USB for AI context: the protocol is the shared shape, so a server you write for one client works for them all. Under the hood it's still the tool-use loop from slide 10.

16
Tutto.Connect & act
Workflows vs agents

Two ways to put it to work

A workflow follows a path you fixed in code. An agent decides its own path at runtime. The choice is simply: can you predict the steps in advance?

Default to a workflow: predictable, cheaper, easy to debug. Reach for an agent only when the path genuinely can't be known ahead of time — that freedom is also the cost.

17
Tutto.Connect & act
Anthropic's apps

The same loop, shipped as products

You don't have to build every agent from scratch. Anthropic ships two that run the tool-use loop over a real environment — and MCP plugs into both.

Computer use is the tool-use loop with a screenshot as the observation and a click as the action — slower and to be sandboxed, but it reaches anything without an API.
