Tutto.Lesson 1 · Foundation
Lesson 1

Chat answers. An agent acts.

Claude.ai hands text back and waits. Claude Code reaches into your files, terminal and codebase and does the work itself.

An agent reads and understands the codebase, edits files across the project, runs terminal commands, and searches the web — then decides what to do next.

03
Tutto.Lesson 2 · Foundation
Lesson 2

The agentic loop

Everything else sits on this: prompt, gather context, act, verify — and loop back until the result holds up.

Four parts make the loop run: the loop itself, a managed context window, tools it can call, and permissions you control. That combination is what a chat window doesn't have.

04
Tutto.Lesson 3 · Setup
Lesson 3

Five places it runs

Same agent, five front doors. Wherever you run it, it can reach that folder and everything beneath it.

Want the cutting edge? Terminal. Want it inside your editor? VS Code or JetBrains. Want it working while you do other things? Desktop. Working from a GitHub repo remotely? Web.

05
Tutto.Lesson 4 · Setup
Lesson 4

One key sets how much you watch

Press Shift + Tab to cycle how hands-on you are. There's no right answer — only what you're comfortable with.

Plan mode is the safe place to start anything complex: it reads your code, asks clarifying questions, and hands back a plan before a single file changes.

06
Tutto.Lesson 5 · The method
Lesson 5 — if you take one thing away

Explore → Plan → Code → Commit

Most people jump straight to "write the code" and course-correct forever. This is the workflow that saves the rework.

Make "correct" explicit (success criteria), give it tools and a test suite to check against, and if it keeps hitting the same wall — tell it to save the fix to CLAUDE.md.

07
Tutto.Lesson 6 · The method
Lesson 6

Context is working memory — it fills up

Every file read, command run and message sent takes space. Three commands keep it usable.

Spend less context: be specific (vague prompts cost more, not less), turn off MCP servers you're not using, and hand exploration to a subagent that returns just the answer.

08
Tutto.Lesson 7 · The method
Lesson 7

Fresh eyes before you push

The agent that wrote the code carries its own bias. A subagent reviews it cold, in its own context.

Keep the reviewer read-only — it flags issues, it doesn't edit. Check it into the repo so the whole team reviews the same way.

09
Tutto.Lesson 8 · Customise
Lesson 8

CLAUDE.md — memory that survives the session

Without it, Claude re-learns your project every time. With it, it starts already onboarded.

It's an onboarding script for your codebase, appended to every prompt. Commit it so the team shares one source of truth — keep it compact and only what's necessary.

10
Tutto.Lesson 9 · Customise
Lesson 9

Subagents — send the heavy lifting away

A subagent does the messy exploration in its own context and hands back only the answer. Your main context stays clean.

"Where are the auth endpoints?" — the subagent reads half the codebase to find out, but only the answer comes back. The journey never clutters your main window.

11
Tutto.Lesson 10 · Customise
Lesson 10

Skills — capability loaded only when needed

A skill advertises itself with a name and one line. Claude loads the full instructions only when it decides to use it.

That's the win over loading everything up front: skills keep the context window lean. (The course points to a dedicated "Introduction to agent skills" for the deep dive.)

12
Tutto.Lesson 11 · Customise
Lesson 11

MCP — a bridge to everything outside the code

Most of your context lives in databases, apps and repos. MCP lets Claude Code reach it through tools.

Watch the cost: every server loads its tool definitions into context, used or not. Run /mcp and disable what you're not using — a CLI like gh, or a Skill, is often leaner.

13
Tutto.Lesson 12 · Customise
Lesson 12

Hooks — the things that must happen, always

A prompt is a request; a hook is a guarantee. Hooks run at fixed points in the lifecycle, every time, no exceptions.

Auto-format on every edit, log every command for compliance, block writes to production. If it needs to happen every time without fail, don't put it in a prompt — put it in a hook.
