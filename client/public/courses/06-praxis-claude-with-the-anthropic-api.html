Tutto.Lesson 1 · Make the call
Lesson 1

One request, and the API forgets you

You send a model, an optional system line, and the whole message list. It replies once. There's no memory — to continue, you append the reply and send it all again.

A "multi-turn conversation" is just this loop run by hand: the model holds nothing between calls, so the growing messages[] list is the memory. Same key, same shape, whatever language you call from.

Tutto.Lesson 2 · Make the call
Lesson 2

Four dials on the same request

You don't change the model to change the behaviour. You turn these.

The system prompt does the heavy lifting — it's where the role and rules live. Temperature trades reliability for variety; streaming is about feel; structured output is how you get data a program can actually use.

Tutto.Lesson 3 · Make it reliable
Lesson 3

Stop guessing whether a prompt is good

An eval is a test suite for prompts: a set of cases, run automatically, graded, scored. Change the prompt, re-run, watch the number move.

Two ways to grade: code-based for anything exact (is it valid JSON? does it contain the answer?), model-based for judgement (is this tactful? is it on-topic?) — you ask another Claude call to score it against a rubric.

Tutto.Lesson 4 · Make it reliable
Lesson 4

Four techniques, in order of leverage

When the output is wrong, you rarely need a bigger model. You need a clearer prompt. Reach for these in order.

Examples (few-shot) move quality the most: a couple of worked input→output pairs teach format and edge cases that paragraphs of instruction can't. XML tags matter because Claude is trained to respect them — <document>…</document> reads cleaner than quotes.

Tutto.Lesson 5 · Extend its reach
Lesson 5 — if you take one thing away

Tool use is a round trip you complete

Claude can't run anything. It can only ask. You describe the tools; it replies "call this, with these arguments"; you run it and hand back the result; it continues.

The loop can repeat — Claude can call several tools across several turns before it answers. This single mechanism is what every agent is built on: the model proposes, your environment executes, the result comes back.

Tutto.Lesson 6 · Extend its reach
Lesson 6

Some tools you don't have to build

Most tools are yours to implement. A few ship with the API — you switch them on and Anthropic runs them server-side.

The text editor and code execution tools are exactly what powers Claude Code and the analysis features. The Files API lets a request reference uploaded files (PDFs, datasets) without re-sending them every call.

Tutto.Lesson 7 · Extend its reach
Lesson 7

RAG — give it knowledge it was never trained on

You can't fit a whole knowledge base in one prompt. So you index it once, then retrieve only the few chunks each question needs and paste them in.

Embeddings catch meaning ("car" finds "vehicle"); BM25 catches exact terms (an error code, a part number). A multi-index pipeline runs both and merges the hits — that's what production RAG actually does.

Tutto.Lesson 8 · Extend its reach
Lesson 8

The same API takes more than text

Four capabilities ride on the request you already know — two change what goes in, two change what comes out.

Extended thinking gives the model room to work through hard problems before committing to an answer. Citations turn "trust me" into "here's the passage" — the backbone of any answer a business has to stand behind.

Tutto.Lesson 9 · Extend its reach
Lesson 9

Pay for the long part once

Most prompts start with the same big block — a system prompt, tool definitions, a document. Cache that prefix and later calls read it instead of re-paying for it.

The rule: only an exact, unchanged prefix is reused, so put everything stable first and the variable part last. Cache lifetimes are short (minutes), so it pays off across a burst of related calls — the heart of any responsive, repeated-context app.

11
Tutto.Lesson 10 · Build systems
Lesson 10

MCP — one standard plug for tools and data

Without it, every app wires up every integration by hand. With it, a server exposes its capabilities once and any client can connect.

A server publishes three things — tools, resources, prompts — and the inspector lets you test it before wiring it to a client. Build the integration once; plug it into Claude Code, your own client, or anyone else's.

12
Tutto.Lesson 11 · Build systems
Lesson 11

Workflows vs agents — who decides the path

Both chain LLM calls. The difference is control: in a workflow you wire the steps; in an agent the model chooses them as it goes.

Choose by predictability. If you can draw the steps in advance, a workflow is cheaper and more reliable. If the path depends on what's found along the way, you need an agent — Claude Code is one. Most production systems mix both.
