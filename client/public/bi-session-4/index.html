One folder per job

This is how the pieces from today fit together. The case folder changes every time. The starting context and the design system stay in one place and get linked in, so you only keep one copy of each.

case-folder/              one per job, named after the case
  CLAUDE.md               read first, in every new chat
  sources/                the case documents: each PDF and its .md text
  output/                 what Claude writes

starting-context/         one copy on your computer, linked in the workspace
  INSTRUCTIONS.md         the standing brief: how this job is done
  VOICE.md                how Background Italia writes (or keep it in CLAUDE.md)
  SCORECARD.md            the checks every draft has to pass
  examples/               a good past report, as text

design-system/            your brand, made in the Claude app, linked the same way

This follows the starter kit: INSTRUCTIONS.md, SCORECARD.md and examples/ are the files in system-template/. Don't worry about getting the layout perfect. Use it, change it and tidy it with Claude when it gets messy.

CLAUDE.md and your voice

Claude reads CLAUDE.md on its own before it does anything in that folder, in every new chat. You don't need to tell it to. Keep the name CLAUDE.md, and copy it into each new folder where you want the same rules.

Whatever you keep correcting by hand belongs in this file. If it writes too much, have it describe a short piece of your writing and turn that description into instructions for itself. It understands its own words best, so let it write them and you approve them. Your voice can live here too, or in a VOICE.md next to it.

Make it write shorter Read the short report in examples/. Describe how it's written: sentence length, how much detail, how it opens and closes. Then write instructions for yourself that make your writing as short as this, and add them to CLAUDE.md for me to approve.
See what it added When you add anything to a report I've written, highlight it so I can see what's yours. Add this rule to CLAUDE.md.

When results start to get worse in a long chat, start a new one. It begins again from CLAUDE.md with a clean head.

Every few months, give your old .md files back to Claude and ask it to make them shorter and easier to use. The tools change, so your files should too.

Scorecards

A scorecard is the job description you'd give a new hire, with the KPIs you'd judge them on. Gabriel called them contracts, which is close. It's as small or as big as the job needs: the more you want it to run on its own, the more exact it has to be.

  1. Simple

    A list in SCORECARD.md

    One to ten things a good draft has. You check it yourself as you read, on the train if that's when you have time.

    No invented facts. Every finding has its source. Written in Italian throughout.

  2. Measured

    Checks with a number

    For review work where a client will spot a gap. Give it a threshold it has to reach, and a way to count.

    Every document in sources/ is cited at least once. Every date matches its source.

  3. Assessment

    A table it fills in first

    Before it drafts, it counts the documents, lists the key facts and flags the holes. This is what an agent runs on its own across several cases.

    Documents 1 to 5 are numbered in sequence. Document 4 is missing.

How hard you check depends on the report too. Alice's rule from your brainstorm is a good first line: on a long report, check the key issues and findings. On a short one, check every detail, because the client accepts fewer mistakes.

The best scorecards come from your own corrections. Gabriel already gives back the revised version and asks Claude to update its instructions. Do that and also say why you changed it, the way you'd brief a subcontractor. You can dictate it. Then share the file, and anyone on the team can run the job to the same standard.

After you correct a draft My corrected version is in output/final.docx. Compare it with your draft. I changed it because <say why>. Update SCORECARD.md so the next draft passes these checks without me making the same changes.

For more on how to think about a scorecard, use the agent scorecard tool.

PDFs into text

PDFs are messy underneath, so Claude has to guess at what's in them and can leave things out. They're also heavy, and copying them into every case folder adds up fast.

Have Claude convert each one to a text (.md) file once, then check the text against the original. The text version is what you keep in your starting context and examples. Keep the PDF only where you need the original.

Convert and check Convert every PDF in sources/ to a .md file with the same name. Keep the tables as tables. Then compare each .md with its PDF and list anything missing: pages, tables, numbers, footnotes.

For work that has to be complete, like litigation, put the comparison in your scorecard so it runs every time. You can also add it to CLAUDE.md: "When I add a PDF, convert it to text and check nothing was lost."

A big archive of old files costs a lot to convert this way. If you get there, ask me: there are cheaper ways to run it in the background.

Workspaces in VS Code

Gabriel was copying his starting-context folder into every new case. A workspace lets each case see that one folder without copying it.

  1. Keep starting-context/ (and later design-system/) in one place on your computer, outside your case folders.
  2. Open the case folder in VS Code as usual.
  3. Drag starting-context/ from File Explorer into the VS Code side panel. When it asks, choose Add Folder to Workspace so nothing gets copied.
  4. Both folders now sit in the side panel. Right-click a file, choose Copy Path and paste it into the chat when you want Claude to use it.
  5. When you close, VS Code asks to save the workspace. Say yes. It saves one small file that remembers which folders this case can see.

Nothing moves on your computer. If you change a file in starting-context/, every case that links it sees the change.

Your brand as a design system

The same idea as the PDFs, for how things look. Give Claude your brand guidelines, presentations, Word files, PDFs or your website. It turns them into a design system: small, exact files for your logo, colours, fonts and spacing.

What it's for

  • Reports and proposals that look the same every time
  • Layout rules you'd otherwise fix by hand, like "a table never splits across two pages"
  • A separate version where Italy and France look different
  • LinkedIn posts in your style, built from your old posts

Where to find it

  • You make it in the Claude desktop app or at claude.ai. It isn't part of VS Code
  • Claude Design has moved into Artifacts, which is why Alice couldn't find it. The old claude.ai/design closes on 14 December 2026
  • Download the folder and link it into your workspace like starting-context/
  • Any web designer could use it, and so can Mistral or another AI

The setup guide takes about 15 minutes and works on your Pro plan: Create a design system in Claude. There's a version for your AI too, if you'd rather it walked you through.
